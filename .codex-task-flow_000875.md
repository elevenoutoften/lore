# Task: flow_000875 — Add actor scoping / 403 on PATCH /api/traces/{id}

## Context

Items #1 (RAG include_traces leak) and #2 (precedent graph path leak) from this task are already closed in commit 7247f4f. The remaining scope is item #3:

PATCH /api/traces/{trace_id} (lore_app/routes/traces.py:93-106 `update_trace`) takes no `Request` and does `get_trace` then `store_trace` with NO actor check, so any writer key can overwrite another actor's trace (status/outcome/reason_summary).

## What to Implement

### 1. Add actor scoping to update_trace
File: `lore_app/routes/traces.py`, function `update_trace` (line 93-106).

Mirror the `get_trace` pattern (line 75-90):
- Add `request: Request` and `cross_actor: bool = Query(default=False)` parameters
- After fetching `existing`, call `recall_actor_scope(request, requested_actor=existing.actor, cross_actor=cross_actor)` inside a try/except PermissionError → 403

The updated function should look like:
```python
@router.patch("/{trace_id}", response_model=TraceEntry)
def update_trace(
    trace_id: str,
    payload: TraceUpdateRequest,
    request: Request,
    cross_actor: bool = Query(default=False),
    ledger: LedgerDB = Depends(get_ledger_db),
) -> TraceEntry:
    """Update an existing trace (e.g., mark completed, add outcome)."""
    existing = ledger.get_trace(trace_id)
    if existing is None:
        raise HTTPException(status_code=404, detail=f"Trace {trace_id} not found")
    try:
        recall_actor_scope(request, requested_actor=existing.actor, cross_actor=cross_actor)
    except PermissionError as exc:
        raise HTTPException(status_code=403, detail=str(exc)) from exc
    update_data = payload.model_dump(exclude_unset=True)
    updated = TraceEntry.model_validate(existing.model_dump() | update_data)
    updated.updated_at = datetime.now(UTC).isoformat()
    return ledger.store_trace(updated)
```

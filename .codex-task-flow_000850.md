# Task: flow_000850 — Fix reader-role MCP write gate bypass via whitespace-padded tool names

## Context

The reader-role MCP lockout was fixed (commit 76c5ec2): auth.py no longer blanket-treats POST /mcp as a write. Write enforcement moved to `routes/mcp.py:mcp_write_call_count` which checks `params.get("name") in WRITE_TOOL_NAMES`.

**BLOCKER (from review):** `mcp_write_call_count` (routes/mcp.py:121) does a raw exact-string membership test: `params.get("name") in WRITE_TOOL_NAMES`. But dispatch normalizes the name via `str(value or '').strip()` (mcp/tools.py:2266) before handler lookup. A reader can bypass the 403 gate by sending a whitespace-padded write tool name (e.g. `"lore_capture "` with trailing space) — the gate doesn't match, but dispatch strips and routes to the write handler. This is a privilege escalation.

## What to Implement

### 1. Normalize tool name in mcp_write_call_count (FAIL-CLOSED)
File: `lore_app/routes/mcp.py`, function `mcp_write_call_count` (line 111-121).

Change line 121 from:
```python
return 1 if params.get("name") in WRITE_TOOL_NAMES else 0
```
to a fail-closed approach: normalize the name with `str(params.get("name") or "").strip()`, then check membership. Unknown/unrecognized names should be treated as writes (fail-closed) — only known READ tools pass through.

Implementation approach: create a `READ_TOOL_NAMES` set = all tool names - WRITE_TOOL_NAMES. The gate returns 0 (read) only if the normalized name is in READ_TOOL_NAMES. Everything else (unknown, padded write, unrecognized) returns 1 (write). This is the robust fail-closed choice the reviewer requested.

### 2. Add lore_ingest_service to WRITE_TOOL_NAMES
File: `lore_app/mcp/tools.py`, line 61-81. Add `"lore_ingest_service"` to the `WRITE_TOOL_NAMES` set for defense-in-depth (currently safe via its own admin guard at tools.py:1677, but should be in WRITE_TOOL_NAMES for consistency).

### 3. Add regression test for whitespace-padded write tool names
File: `tests/test_auth.py`. Add a test `test_reader_mcp_rejects_whitespace_padded_write_tools` that:
- Creates a reader-role key
- POSTs to /mcp with `params.name` = write tool names with trailing space, leading space, and tab padding (e.g. `"lore_capture "`, `" lore_capture"`, `"\tlore_capture\t"`)
- Asserts each returns 403
- Also test a batched tools/call payload (list with one padded write call) returns 403

### 4. Add lore_recall and lore_read_page to reader-read assertions
File: `tests/test_auth.py`, function `test_reader_mcp_can_read_but_not_write` (line 402). After the existing `lore_search` assertion (line 443-452), add two more read tool calls:
- `lore_recall` with `arguments: {"query": "test"}`
- `lore_read_page` with `arguments: {"page_id": "concepts/test"}` (or any valid page_id)

Assert both return 200 (not 403).

## Files NOT to Modify

- Any other routes, services, or modules

# Codex Task: L-PATCH-01 — Make patch planner section/span-aware

## Context

`patch_planner.py:505-512` does `new_content.replace(old_object, replacement, 1)` when updating an existing fact. This matches the first occurrence of the old text ANYWHERE in the page — including frontmatter, code blocks, links, or unrelated sections. This can corrupt pages.

## What to Implement

### 1. Section-aware replacement in `update_existing_fact`

In `lore_app/patch_planner.py`, modify the `update_existing_fact` logic to:

a) Extract the claim's section/span from candidate metadata. If the candidate `content_json` has a `section` or `anchor` field, use it to locate the correct markdown section (identified by `## Section Title`).

b) Split the page content into sections using markdown headings. Find the targeted section by matching the section title.

c) Apply the `old_object → replacement` substitution ONLY within that section's text.

d) If no section/anchor metadata is available, or if the old_object appears in multiple sections (ambiguous), mark the patch with `status = "needs_manual_review"` and add a `reason` field like `"Ambiguous match: '[old_object]' found in multiple sections or no section anchor available."` instead of performing the replacement.

### 2. Protect frontmatter and fenced code blocks

Before any replacement:

a) Split off YAML frontmatter (between `---` markers). Never modify frontmatter content.

b) Protect fenced code blocks (``` ... ```). If `old_object` appears entirely within a code block, skip it and continue searching.

### 3. Add `_find_section` helper

Add a helper that splits markdown into sections by headings:

```python
def _split_into_sections(content: str) -> list[tuple[str, str]]:
    """Split markdown content into (title, body) sections by ## headings."""
    sections = []
    current_title = ""
    current_lines = []
    for line in content.split("\n"):
        if line.startswith("## "):
            if current_lines:
                sections.append((current_title, "\n".join(current_lines)))
            current_title = line[3:].strip()
            current_lines = [line]
        else:
            current_lines.append(line)
    if current_lines:
        sections.append((current_title, "\n".join(current_lines)))
    return sections
```

### 4. Add dataclass for patch review status

In `lore_app/schemas.py` or `lore_app/patch_planner.py`, add:

```python
class PatchPlanStatus(str, Enum):
    ready = "ready"
    needs_manual_review = "needs_manual_review"
```

Use this in the `PatchPlan` model (or whatever represents a planned patch). Patches that are ambiguous should have `status="needs_manual_review"` and a `reason` field.

### 5. Tests

In `tests/test_patch_planner.py`, add three tests:

a) `test_update_existing_fact_targets_correct_section` — Page with two sections, claim in section 2. Verify replacement only affects section 2, not section 1.

b) `test_update_existing_fact_ambiguous_match_needs_manual_review` — `old_object` appears in multiple sections and no section anchor provided. Verify patch has `status="needs_manual_review"`.

c) `test_update_existing_fact_protects_frontmatter_and_code_blocks` — `old_object` appears in both frontmatter and a code block AND in the target section. Verify only the target section occurrence is replaced.

# L-POLICY-01: Add versioned consolidation policy definitions

## Context

PatchPlanner currently hard-codes auto-apply rules, risk assessment, and protected page kinds. This task extracts those rules into versioned policy definitions with stable IDs so traces and patch plans can cite them.

## What to Implement

### 1. Create `lore_app/policies.py` with policy data models

```python
from __future__ import annotations
from pydantic import BaseModel, Field

class PolicyRule(BaseModel):
    """A single rule within a policy."""
    rule_id: str
    description: str
    condition: str  # Machine-readable condition expression
    effect: str     # "allow" | "deny" | "require_review"

class PolicyDefinition(BaseModel):
    """A versioned policy definition."""
    policy_id: str          # e.g. "POL-001"
    version: int             # Monotonically increasing version
    name: str               # e.g. "Protected Surface Policy"
    description: str
    rules: list[PolicyRule] = Field(default_factory=list)
    created_at: str
    updated_at: str | None = None
```

### 2. Create `data/policies/` directory with default policy YAML files

Create 5 default policies as YAML files that reproduce the current PatchPlanner behavior:

**data/policies/POL-001.yaml** — Protected Surface Policy:
```yaml
policy_id: POL-001
version: 1
name: Protected Surface Policy
description: >-
  Pages of kind decision, runbook require manual review before any
  patch can be auto-applied. Current behavior before POLICY-01.
rules:
  - rule_id: POL-001-R01
    description: Decision and runbook pages require review.
    condition: "page.kind in ['decision', 'runbook']"
    effect: require_review
  - rule_id: POL-001-R02
    description: Decision pages always get high risk.
    condition: "page.kind == 'decision' and plan.operation != 'create_stub_page'"
    effect: deny
created_at: "2026-05-22T00:00:00+00:00"
```

**data/policies/POL-002.yaml** — Trust Threshold Policy:

# L-CI-01: Add lint, coverage, and dependency-audit gates to CI

## Context

`.github/workflows/ci.yml` runs tests, package build, SDK tests, and Docker startup but has
no ruff, type-check, coverage threshold, dependency audit, or secret-scan job. `pyproject.toml`
has pytest config but no lint/type/coverage tool config. The repo can regress on style,
typing, dead code, untested modules, and vulnerable deps without CI catching it.

## Current State

**ci.yml jobs:** test (2 Python versions), package, python-sdk, typescript-sdk, docker.
No lint, coverage, type-check, or audit jobs exist.

**pyproject.toml:** Has `[tool.pytest.ini_options]` with testpaths and markers. No `[tool.ruff]`,
no `[tool.coverage]`, no mypy config.

**Installed test deps:** Only pytest and pytest-timeout in `[project.optional-dependencies].test`.

**Test count:** 513 tests collected.

## What to Implement

### Step 1: Add ruff configuration to pyproject.toml

```toml
[tool.ruff]
target-version = "py311"
line-length = 120
src = ["lore_app", "tests"]

[tool.ruff.lint]
select = ["E", "F", "W", "I", "UP", "B", "SIM", "TCH", "RUF"]
ignore = ["E501"]  # line length handled by formatter

[tool.ruff.lint.isort]
known-first-party = ["lore_app"]

[tool.ruff.format]
quote-style = "double"
```

### Step 2: Add coverage configuration to pyproject.toml

```toml
[tool.coverage.run]
source = ["lore_app"]
omit = ["lore_app/__main__.py"]

[tool.coverage.report]
fail_under = 50
show_missing = true
exclude_lines = [
    "pragma: no cover",
    "if __name__ == .__main__.:",
    "pass",
]
```

Note: Use `fail_under = 50` as a starting threshold (current coverage is unknown but
likely below 70%). This gate can be raised once baseline is established.

### Step 3: Add ruff and coverage dev deps

Add to `[project.optional-dependencies]`:

```toml
[project.optional-dependencies]
test = [
  "httpx>=0.27,<1.0",
  "pytest>=8.0,<9.0",
  "pytest-timeout>=2.3,<3.0",
  "pytest-cov>=5.0,<7.0",
]
dev = [
  "lore[test]",
  "ruff>=0.5,<1.0",
]
```

### Step 4: Add CI jobs to .github/workflows/ci.yml

Add three new jobs parallel to `test`:

```yaml
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.11"
      - name: Install dev deps
        run: pip install -e ".[dev]"
      - name: ruff check
        run: ruff check .
      - name: ruff format --check
        run: ruff format --check .

  coverage:
    runs-on: ubuntu-latest
    env:
      LORE_CONTENT_DIR: /tmp/lore-ci-pages
      LORE_SEARCH_DB: /tmp/lore-ci-db/search.db
      LORE_VECTOR_DB: /tmp/lore-ci-db/vectors.db
      LORE_LEDGER_DB: /tmp/lore-ci-db/ledger.db
      LORE_API_KEYS_DB: /tmp/lore-ci-db/api-keys.db
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.11"
      - name: Install test deps
        run: pip install -e ".[test]"
      - name: Run coverage
        run: |
          rm -rf /tmp/lore-ci-db /tmp/lore-ci-pages
          mkdir -p /tmp/lore-ci-db /tmp/lore-ci-pages
          python -m pytest tests/ eval --timeout=60 --cov=lore_app --cov-report=term-missing

  dependency-audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.11"
      - name: Install pip-audit
        run: pip install pip-audit
      - name: pip-audit
        run: pip-audit --desc
```

The existing `package`, `python-sdk`, `typescript-sdk`, `docker` jobs still depend on `test`.
The new `lint`, `coverage`, `dependency-audit` jobs are independent (no `needs:`) so they
run in parallel with `test`.

### Step 5: Verify locally

```bash
cd /home/nyx/.hermes/projects/lore && .venv/bin/pip install ruff pytest-cov pip-audit && \
.venv/bin/ruff check . && \
.venv/bin/ruff format --check . && \
rm -rf /tmp/lore-test-db /tmp/lore-test-pages && \
.venv/bin/python -m pytest tests/ eval --timeout=60 --cov=lore_app --cov-report=term-missing -q 2>&1 | tail -20
```

If `ruff check` has many violations (common in existing codebases), add a `--fix` pass first
to auto-format, then review remaining issues. If violations block the CI gate, temporarily
lower the bar:
- In ci.yml lint job, add `continue-on-error: true` for the first run(s)
- Or narrow the ruff selector to just `[E, F, I]` initially

The goal is to have the gates *exist* and pass on the current codebase, not to achieve
zero warnings on day one. If there are too many existing violations, add `--exit-zero` for
the initial commit and create a follow-up task for addressing violations.

If `pip-audit` finds vulnerabilities, only fail on high/critical. Add `--ignore-vuln` for
known low-severity issues with a comment explaining why.

## What NOT to Modify

- Do NOT change existing test code or assertions
- Do NOT modify any application code to fix lint warnings (that's a separate task)
- Do NOT remove any existing CI jobs
- Do NOT change the existing test job's Python version matrix
- Do NOT add mypy/pyright (optional per task spec; keep it light for now)
- Do NOT change the Docker job's environment variables

## Acceptance Criteria

1. `[tool.ruff]` and `[tool.coverage]` sections exist in `pyproject.toml`
2. `[project.optional-dependencies].dev` includes ruff
3. `[project.optional-dependencies].test` includes pytest-cov
4. `ci.yml` has three new parallel jobs: `lint`, `coverage`, `dependency-audit`
5. `pip install -e ".[dev]"` succeeds
6. `ruff check .` passes (or `--exit-zero` with documented exceptions)
7. `pytest --cov=lore_app --cov-report=term-missing` runs and reports coverage
8. `pip-audit` runs without errors for core dependencies
